# 数据库变更安全规范

适用场景：新增/修改/删除表、字段、索引、约束、初始数据、数据迁移。

## 执行前

1. 先检查现有数据库结构和相关代码。
2. 生成 SQL 前核对字段长度、类型、约束，避免导入时截断或冲突。
3. 准备备份和回滚脚本。

## SQL 要求

1. 输出完整可执行的 SQL，包含回滚方案。
2. 迁移脚本必须幂等（重复执行不报错不重复写入）。
3. 兼容所有目标数据库版本（生产、测试、CI）。
4. `CREATE TABLE IF NOT EXISTS` 不会升级已存在的旧表结构，需要单独处理（如按字段存在性判断后 `ALTER TABLE`）。

## 数据合并

1. 本地和线上同一业务记录的主键可能不同，合并时按业务键匹配，不按主键。
2. 同名判断先做标点和空格归一化。

## 验证

1. 先做事务预演，确认无误后再回滚预演事务。
2. 在所有目标数据库版本上做隔离验证。
3. 迁移脚本至少执行三次验证幂等。
4. 执行 SQL 后立即进入后端开发。
