# 调试与部署排查

## 排查与修复

用户明确说"先排查""不改代码""列出来"时，严格只读分析，等明确指令再动手。其他情况下排查定位后直接修复。

## 前端排查顺序

1. 确认后端服务已启动，且运行在正确的分支。
2. 检查浏览器控制台是否有报错。
3. 检查网络请求的 URL、参数、响应状态码和响应体。
4. 检查接口代码生成是否与后端一致。
5. 验证页面路由、组件渲染、数据绑定。

## 后端排查顺序

1. 查看服务启动日志是否有异常。
2. 运行构建和测试命令检查编译和测试。
3. 检查接口返回的状态码和数据结构。
4. 验证数据库查询结果与预期是否一致。

## 常见"幽灵 bug"来源

- 后端没重启或进程跑在旧分支上。
- 增量编译产物过期，重新完整编译即可。
- Git 冲突标记残留在代码中导致运行时报错。
- 环境变量或配置文件没传进容器。
- 用户报"合并冲突"时，先区分是真正的 Git 冲突还是 CI Pipeline 失败。

## 部署排查

- 检查环境变量和配置文件是否完整传入。
- 检查容器日志。
- 域名或地址变更时逐项核对：CORS、前端 API 地址、反向代理、证书。
- 非 HTTPS 环境下部分浏览器 API 不可用，需要降级兼容。
