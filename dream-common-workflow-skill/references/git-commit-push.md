# 提交、推送与 Merge Request

## 通用规则

1. 不直接向主分支提交或推送。新建功能分支，开发完成后创建合并请求。
2. 只暂存与本次需求相关的文件，不提交无关改动。
3. 保留开发者现有未提交内容，不覆盖、不回退、不删除。
4. 提交前运行完整的构建、测试和代码规范检查，全部通过后才提交。
5. 使用有意义的中文提交信息，描述本次改动的内容。
6. 调试时修改的临时配置（端口、地址、密钥）不得提交。
7. 接口代码生成后检查 diff，确认生成的类型文件已纳入暂存，无关删除已撤销。
8. stash 恢复后先检查是否有冲突标记残留。

## 前端提交并推送

为当前已完成的需求新建或签出功能分支，提交并推送代码，然后按照项目流程创建 Merge Request，并配置为满足条件后自动合并。

1. 检查当前 Git 状态、所在分支以及本地已有分支。
2. 以本地项目的主分支为基准处理功能分支：
   - 如果当前需求对应的 `dev`、`feature/*` 等功能分支已经存在，直接签出并切换到该分支。
   - 如果对应的功能分支不存在，则从主分支（如 `master`）创建并切换到新的功能分支。
3. 保留开发者现有改动，不得覆盖、回退或删除尚未提交的内容。
4. 只暂存与本次需求有关的文件。
5. 提交前运行类型检查和代码规范检查，例如：

   ```bash
   npm run type-check
   npm run lint
   ```

6. 使用中文 Git 提交信息创建提交。
7. 将当前功能分支推送到远程。
8. 创建合并到主分支的 Merge Request，并配置为满足条件后自动合并。

## 后端提交并推送

为当前已完成的后端需求新建或签出功能分支，提交并推送代码，然后按照项目流程创建 Merge Request，并配置为满足条件后自动合并。

1. 检查当前 Git 状态、所在分支以及本地已有分支。
2. 以本地项目的主分支为基准处理功能分支：
   - 如果当前需求对应的 `dev`、`feature/*` 或其他功能分支已经存在，直接签出并切换到该分支。
   - 如果对应的功能分支不存在，则从主分支创建并切换到新的功能分支。
3. 保留开发者现有改动，不得覆盖、回退或删除尚未提交的内容。
4. 只暂存与本次后端需求有关的文件。
5. 提交前运行后端测试与构建。
6. 使用中文 Git 提交信息创建提交。
7. 将当前功能分支推送到远程。
8. 推送成功后，自行创建从当前功能分支合并到主分支的 Merge Request，并配置为满足条件后自动合并。

## 合并请求工具

- GitHub：`gh pr create`，自动合并用 `gh pr merge --auto --merge`（需仓库开启 auto-merge）。
- GitLab：`glab mr create`，自动合并用 `--auto-merge` 或在 MR 中设置"流水线成功后合并"。
