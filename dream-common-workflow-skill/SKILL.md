# 通用开发流程

适用于任意语言、任意框架的前后端项目。从项目实战中提炼，去掉了具体技术栈和项目细节。

## 使用方式

1. 先判断当前任务属于哪一类：开发、调试、数据库变更、回滚、提交推送。
2. 用户说"先排查""不改代码""列出来"时，进入只读模式：只做分析和输出，不修改任何文件，等明确指令再动手。其他情况下排查定位后直接修复。
3. 按下方对应章节执行；细节规范见 `references/` 下的文件：
   - 数据库变更安全规范：[references/database.md](references/database.md)
   - 调试与部署排查：[references/debugging.md](references/debugging.md)
   - 提交、推送与 Merge Request：[references/git-commit-push.md](references/git-commit-push.md)

## 一、开发阶段

开发按阶段推进，每个阶段完成后自动进入下一阶段，中间不停顿：

数据库变更（如涉及） -> 后端开发 -> 前端开发 -> 联调 -> 提交推送

### 1.1 数据库变更（如涉及）

适用场景：新增/修改/删除表、字段、索引、约束、初始数据、数据迁移。

1. 先检查现有数据库结构和相关代码。
2. 输出完整可执行的 SQL，包含回滚方案。
3. 迁移脚本必须幂等（重复执行不报错不重复写入）。
4. 兼容所有目标数据库版本（生产、测试、CI）。
5. 涉及数据合并时，按业务键匹配，不按主键。同名判断先做标点和空格归一化。
6. 执行 SQL 后立即进入后端开发。

执行前遵循 [references/database.md](references/database.md) 中的安全规范。

### 1.2 后端开发

1. 按层级依次完成：实体/模型 -> 数据访问层 -> 业务层 -> 接口层。
2. 权限校验独立于前端，前端按钮只控制显示，后端必须独立鉴权。
3. 防止通过替换资源 ID 或关联 ID 越权。
4. 大整数业务标识（如雪花 ID）按字符串传递，不做数值转换。
5. 完成后运行项目的构建和测试命令，确认全部通过。
6. 测试使用隔离的内存数据库或模拟环境，不得连接真实外部服务。
7. 禁止跳过测试或删除测试来通过 CI。
8. 完成后输出交接文档（handoff），描述接口路径、参数、返回结构、权限要求。
9. 后端通过后立即进入前端开发。

### 1.3 前端开发

1. 先同步后端接口定义（如 OpenAPI 代码生成），检查生成文件的 diff，撤销无关变更。
2. 生成的接口代码如果与后端实际行为不一致，先回到后端修正，不在前端猜测。
3. 筛选项、分类、标签等动态数据由接口驱动，不硬编码。
4. 大整数 ID 全链路保持字符串：保存、比较、拼接 URL、发送请求。
5. 后端返回的数值字段先做类型转换再计算，防止字符串拼接。
6. 大批量 ID 参数不要拼进 GET URL，改为分批请求或 POST。
7. 完成后运行类型检查和代码规范检查。
8. 前端通过后立即进入联调。

### 1.4 联调

1. 先确认后端服务已启动且运行在正确的分支上。
2. 检查前端代理配置指向正确的后端地址和端口。
3. 验证场景：正常流程、参数错误、未登录、无权限、不同角色的数据范围。
4. 验证替换关联 ID 后返回无权限或资源不存在，不泄露数据。
5. 检查浏览器控制台无未处理的报错，网络请求无未处理的 4xx/5xx。
6. 联调通过后立即提交推送，流程见 [references/git-commit-push.md](references/git-commit-push.md)。

## 二、回滚规范

1. 回滚前先列出受影响的文件清单。
2. 回滚前先做备份。
3. 按需求维度精确回滚，不做无差别的全量回滚。
4. 回滚后检查是否"回滚过头"，确认不相关的改动仍然保留。

## 三、工作风格

### 3.1 需求与交接

- 大功能先输出开发清单，确认后再按清单开发。
- 需求不清时先打磨需求文档，不改代码，打磨好再执行。
- 后端完成后输出交接文档（handoff）。

### 3.2 只读模式

用户说"先排查""不改代码""列出来"时，只做分析和输出，不修改任何文件。

### 3.3 测试范围

- 日常开发按改动范围做增量验证。
- 提交阶段才跑全量构建和测试。

### 3.4 视觉还原

- 以设计原型为准，有歧义时先确认再动手，不反复猜。
- 用户给了 DOM 选择器或 CSS 属性时，严格按指定位置和样式实现。
- 深色/浅色模式都要检查。

## 四、通用开发约束

1. 大整数业务 ID 全链路字符串传递，禁止数值转换。
2. 权限校验后端独立实现，不依赖前端显示控制。
3. 测试环境隔离，不连接真实外部服务。
4. 禁止跳过测试，禁止删除测试来通过 CI。
5. 过滤规则一次写全，用全量数据验证，不做"差不多"的实现。
6. 筛选项和分类由接口数据驱动，不硬编码。
7. 环境相关的临时配置不得提交到代码仓库。
8. 凭据不要明文粘贴在对话或代码中，使用环境变量或临时凭据。
9. 回滚按需求维度精确执行，回滚后核查范围。
10. 遇到业务语义不确定时，不自行推断，按用户明确说的来。
